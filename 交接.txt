# mine2digest 完整设计规格

> 项目定位：**批量半自动文献检索 + 论文写作材料抽取**。从检索获取（mining）到证据提炼（digest），输出可直接支撑论文写作的结构化材料。

---

## 一、核心设计原则（vibe coding 时不要跑偏的五条）

1. **无人工校准**。全流程唯一人工动作是：把 `fail_list` 里自动获取失败的闭源 PDF 丢进 `inbox/`。其余判断全部由规则 + 双 agent 自动完成。
2. **用途向量，不是相关性标量**。每篇论文的输出是“将在论文的哪一节、以什么角色被消费”，不是“相关/不相关”。
3. **可追溯的丢弃**。任何被丢弃或降级的论文都保留元信息和投票日志，写作阶段可按 `paper_id` 回溯捞回。
4. **SQLite 是唯一真相源，CLI 是唯一写入口**。agent 永远不直接读写 `db/*.sqlite` 或 `exports/`；只通过 `mine2digest <command>` 读写，stdin/`--file` 进，stdout 出 JSON。
5. **A/B 是流水线并行，C 部分并行**。A 流式产出 `status=fetched`，B 流式消费；C1（结构模板）和 C3（图表）可与 B 并行，C2（覆盖矩阵）和 C4（草稿）必须等 B 的证据卡基本齐。

---

## 二、整体流程与并行关系

```text
A1 种子发现（OpenAlex）
   ↓
A2 引用扩展（Semantic Scholar，一跳，只留 influential/methodology/result）
   ↓
A3 双 agent 用途分档（agent A 与 agent B 独立投票 → 合并）
   ↓
A4 自动获取（Unpaywall → arXiv → OpenReview → PMC，流式产出）
   │
   ├── 成功 → papers/{slug}/paper.pdf → status=fetched ──┐
   └── 失败 → fail_list.json → 人工放 inbox/ → ingest-manual
                                                          ↓
B1 全文阅读（多篇并发）→ 用途级证据卡
   ↓
B2 locator 自动校验（同步，失败回滚）── 硬门
   ↓
B3 反证 agent（用途级追问 caveat）
   ↓
B4 审计 agent（抽 10%，只标记不阻断，内化为 source_reliability 权重）
   ↓
C1 结构模板抽取 ──┐（可与 B 并行，provisional 标记）
C3 图表生成 ──────┤（可与 B 并行，完全不依赖 B）
C2 覆盖矩阵 ──────┘（必须等 B 的卡基本齐；空格自动回溯 low_priority）
   ↓
C4 逐节草稿 + evidence_ref 回溯校验（节间并行，节内先绑定证据再打磨措辞）
```

**背压机制**：`next-fetch` 只取 `status=queued` 的论文，`next-reading` 只取 `status=fetched`。B 的 worker 拉不到就空转等待，A4 产出后自动被消费，不需要消息队列或调度器。

## 四、用途标签体系（系统核心）

### 4.1 枚举（`config/labels.yaml`）

```yaml
use_types:
  - support_claim        # 支撑某个论点
  - baseline             # 直接对比基线
  - method_borrow        # 可借鉴的方法模块
  - experiment_design    # 可参照的实验/消融设计
  - gap_evidence         # 证明研究缺口的证据
  - contradict           # 反对/限定某结论
  - style_sample         # 写作结构/视觉风格样本
  - background           # 背景，无具体可消费元素

target_sections:
  - intro
  - related_work
  - method
  - experiments
  - discussion

priority_weights:        # fetch 队列排序 = 确认用途类型权重之和
  baseline: 1.0
  gap_evidence: 1.0
  support_claim: 0.8
  contradict: 0.8
  method_borrow: 0.7
  experiment_design: 0.7
  style_sample: 0.3
  background: 0.1

thresholds:
  vote_confidence_min: 0.5
  locator_fuzz_min: 75
  audit_rate: 0.1
  audit_pass_min: 0.7
  audit_window: 200
```

### 4.2 投票 schema（每个 agent 输出）

```json
{
  "paper_id": "...",
  "topic_relevant": true,
  "uses": [
    {
      "type": "baseline",
      "target_section": "experiments",
      "anchor": "一句话：这篇为我的论文做什么",
      "confidence": 0.0
    }
  ]
}
```

**硬约束**：`type` 和 `target_section` 必须在枚举内，`submit-vote` 时校验，非法直接拒绝（不静默纠正）。同一 `(type, target_section)` 不重复。

### 4.3 双 agent 合并规则（`merge_votes` 纯函数）

| 情况 | 动作 |
|---|---|
| 双方都有该用途，且 confidence 均 ≥ 0.5 | **确认用途**，`needs_fulltext_confirm=false` |
| 双方都有，一高一低（低者 < 0.5） | 保留高置信版本，`needs_fulltext_confirm=true`，仍确认 |
| 仅一方标注 | 进 **disagreement**，论文仍可能因其他确认用途进入 fetch |
| 双方都只有 `background` | `decision=low_priority`（元信息保留，不下载） |
| 双方都无任何用途，且都 `topic_relevant=false` | `decision=discard`（日志留痕） |
| 双方都无任何用途，但至少一方 `topic_relevant=true` | `decision=low_priority` |

**决策输出**：

- `fetch`：存在非 background 的确认用途 → 计算 `priority = Σ priority_weights[type]`，入 `fetch_queue`，`status=queued`
- `low_priority`：`status=low_priority`，元信息保留
- `discard`：`status=discarded`，日志留痕

## 五、数据模型（SQLite schema）

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;

papers (
  paper_id TEXT PK, doi TEXT, title TEXT NOT NULL,
  abstract TEXT,                    -- ★ 迭代1新增，供筛选 agent 用
  year INTEGER, venue TEXT, source TEXT,
  status TEXT NOT NULL DEFAULT 'candidate',
  added_at TEXT, updated_at TEXT
)
-- status 状态机：
-- candidate → screened → queued → fetching → fetched
--                    → low_priority
--                    → discarded
-- fetched → confirming → confirmed / rejected

relations (src_id, dst_id, relation, is_influential, contexts, PK(src,dst,rel))

screening_votes (
  vote_id PK, paper_id, agent_id, uses_json, topic_relevant,
  created_at, UNIQUE(paper_id, agent_id)
)

screening_merged (
  paper_id PK, merged_uses, decision, priority, disagreement, merged_at
)

fetch_queue (paper_id PK, priority, enqueued_at, claimed_at, claimed_by)

fetch_attempts (attempt_id PK, paper_id, source, url, success, error, attempted_at)

evidence_cards (
  card_id PK, paper_id, use_type, target_section,
  claim, evidence_locator, source_span, method_snippet,
  caveat, confidence, stage,              -- fulltext_confirmed | fulltext_discovered | rejected
  locator_status,                         -- pending | verified | unverified | failed
  original_prediction, created_at
)

locator_checks (card_id PK, match_ratio, matched_text, checked_at)

audit_samples (card_id PK, passes, reason, sampled_at)

source_reliability (source PK, weight, updated_at)

state_transitions (id PK, paper_id, from_status, to_status, command, at)
```

**关键索引**：`papers(status)`、`screening_merged(decision, priority DESC)`、`evidence_cards(target_section, use_type, stage)`、`state_transitions(paper_id, at)`。

## 六、CLI 接口契约

**统一规则**：输入 JSON（stdin 或 `--file`），输出 JSON（stdout）。成功 `{"ok": true, ...}`，失败 `{"ok": false, "reason": "...", ...}` 且退出码 1。所有命令自动追加 `logs/cli.jsonl`。

### 阶段 A

| 命令 | 输入 | 作用 |
|---|---|---|
| `add-candidates --file --source` | 原始 JSONL | 批量插入，`status=candidate`，去重键 doi → openalex_id → s2_id → sha1(title.lower()) |
| `add-relations --file` | 引用边 JSONL | 写 `relations`，`INSERT OR REPLACE` |
| `next-candidates --agent-id --limit` | 无 | 取未被该 agent 投票的 `candidate`，带出 `citation_contexts` |
| `submit-vote --agent-id --file` | 投票 JSON | 校验枚举 + 状态，UPSERT（同 agent 幂等覆盖） |
| `tally-votes --batch --agent-a --agent-b` | 无 | 合并双票，写 `screening_merged` + `fetch_queue` + 状态迁移 |
| `next-fetch --limit --worker` | 无 | `UPDATE ... RETURNING` 原子认领，`status=fetching` |
| `report-fetch --paper-id --status --path --source` | 无 | 成功→归档 `papers/` + `meta.json`；失败→写 `fetch_attempts` |
| `ingest-manual --file --doi --title` | 无 | 从 `inbox/` 移入 `papers/`，补 `meta.json`，`status=fetched` |

### 阶段 B

| 命令 | 作用 |
|---|---|
| `next-reading --limit` | 取 `status=fetched`，带 `merged_uses` + `disagreement` + 预提取页文本 |
| `add-card --file` | **事务内**逐条插入 + 同步 locator 校验，任一失败整卡回滚 |
| `verify-card --card-id` | 单独重跑 locator 校验 |
| `add-caveat --card-id --file` | 反证结果绑定到具体用途 |
| `next-caveat --limit` | 取 `caveat IS NULL` 且 `fulltext_confirmed` 的卡 |
| `audit --rate` | `ORDER BY RANDOM() LIMIT n` 抽样写 `audit_samples` |
| `submit-audit --file` | 回填结果，触发 `source_reliability` 更新 |
| `reject-card --card-id --reason` | `stage=rejected` |

### 阶段 C

| 命令 | 作用 |
|---|---|
| `coverage --sections` | 覆盖矩阵（section × type），空格查 `low_priority` 标 `reclaimable` |
| `query --type --section --min-confidence` | 按格子拉证据卡（带 caveat） |
| `lookup --paper-id` | 单篇全信息（含 rejected 用途，回溯用） |
| `export --view` | 从 DB 导出到 `exports/` |
| `draft --section` | 读结构模板 + 覆盖矩阵 + 证据卡，逐段生成草稿 |
| `verify --file` | 独立校验草稿里所有 `evidence_ref` 的回溯有效性 |

### 服务模式（可选，仅读）

`mine2digest serve --read-only --port 8765`，只暴露 `GET /coverage`、`GET /query`、`GET /card/{id}`。**写操作永远走 CLI**。

## 七、并发与一致性

- **写路径**：一律 `BEGIN IMMEDIATE`（`db.tx()`），读路径不用事务包装。
- **双 agent 同时投票**：`UNIQUE(paper_id, agent_id)` 保证各一行，`tally-votes` 只处理双方都投了的论文，不需要显式锁。
- **多论文并行 `add-card`**：每篇一个事务，locator 校验在事务内，失败回滚整卡。
- **fetch 认领**：`UPDATE fetch_queue SET claimed_at=... WHERE paper_id IN (SELECT ... WHERE claimed_at IS NULL ORDER BY priority DESC LIMIT n) RETURNING *`（SQLite 3.35+）。
- **崩溃恢复**：WAL 天然支持；`papers.status` 是唯一状态机，崩溃后按状态补跑对应 `next-*` 即可。
- **locator 文本缓存**：`papers/{slug}/extracted/page-{n}.txt` 首次提取后落盘，后续校验读文件不重解 PDF。

## 十、已知待办与决策点

### 10.1 agent_id 对齐问题（建议下一迭代先解决）

当前 `submit-vote --agent-id` 是自由字符串，`tally-votes --agent-a/--agent-b` 默认 `A/B`。若 prompt 里 agent 自报 `agent_a` 就 tally 不出东西。

**方案**：`config/labels.yaml` 加 `agent_ids: [A, B]`，`submit-vote` 校验 `agent_id ∈ agent_ids`，`tally-votes` 从配置读而非 CLI 参数。需同步改 `a_screen.py` 和 `test_screening_cli.py`。

### 10.2 迭代 1b 的细节

- `add-candidates` 去重键优先级：`doi` → `openalex_id` → `s2_id` → `sha1(title.lower())`。已存在记录只更新 `updated_at`，**不覆盖 `status`**。
- `add-relations` 的 `contexts` 字段 JSON 序列化；S2 扩展脚本单独放 `scripts/s2_expand.py`，不塞进 CLI。

### 10.3 迭代 1c 的细节

- 四个 fetcher 统一接口 `try_fetch(paper: dict) -> (success, path_or_url, error)`。
- `report-fetch --status failed` 写 `fetch_attempts`（每个 source 一行），`status=fetch_failed`，按 `--retry` 决定是否清 `claimed_at` 允许重试。
- `ingest-manual` 校验 `inbox/` 文件存在 → 移入 `papers/{slug}/paper.pdf` → 写 `meta.json`（`version` 由 `--version` 参数指定，默认 `preprint`）。

### 10.4 迭代 1d 的细节

- `extract.py`：PyMuPDF 按页提取，写 `extracted/page-{n}.txt`，幂等（已存在则跳过）。
- `locator.py`：解析 `"p.7, Table 3"` → 页码 `[7]`；解析失败则全文拼起来扫，记录命中页。`rapidfuzz.fuzz.partial_ratio(source_span, page_text) >= 75` 通过，记录 `match_ratio` 和 `matched_text`。
- `add-card` 事务内：枚举校验 → 逐条 `INSERT` → 同步 `verify_locator` → 失败 `raise LocatorError` 触发 `ROLLBACK`。

### 10.5 迭代 2 的细节

- `audit` 的 `source_reliability` 更新逻辑：取最近 `audit_window=200` 条 `audit_samples`，按论文 `source` 聚合，`pass_rate < 0.7` 则 `weight *= 0.9`（下限 0.5）。
- `coverage` 输出时用 `labels.yaml` 枚举**补全空格子**（`n=0` 显式输出，不省略），空格查 `low_priority` 标 `reclaimable: true`。

### 10.6 迭代 3/4 的细节

- `templates extract` 的 `provisional` 标记：`style_sample` 已确认的优先；不足时 fallback 到 venue 匹配的 `fetched` 论文，`provisional=true`。C4 用模板前检查 `provisional` 源论文是否已被 B 整体证伪（`status=rejected`），是则跳过。
- `draft` 的每句 claim 强制带 `evidence_ref`，格式建议 `[[card:{card_id}]]`，`verify` 用正则扫描。
- `figures generate` 包 PaperBanana CLI：`paperbanana generate --input method.txt --caption "..."`，产物 `.png` + `.src.py` + `.manifest.json`。
